  6. Styling and Design — inline and external CSS, SLDS, design tokens, shared CSS, dynamic CSS, styling across Shadow DOM, and Lightning Design System.
  7. Lifecycle and Rendering — lifecycle hooks, render method, mounting, unmounting, error handling, and render strategy.
  8. Navigation — navigation service, navigate to home, chatter, record pages, list views, files, Aura, Visualforce, and current page reference.
  9. Working with Data — Lightning Data Service, base Lightning components, lightning-record-form/view/edit/form, reset/edit forms, custom validation, @wire service, getObjectInfo, picklist adapters, getRecord, getListUi, create/update/delete record.
  10. Apex and Server Integration — expose Apex methods, import Apex, wire/Apex methods with parameters, imperative Apex calls, refreshApex, and build real apps like book listings.
  11. Advanced UI Features — PDF generation, maps, filtering, sorting, charts, reusable modal components, date validation, CSV generation, custom carousel, third-party JS/CSS libraries, static resources, and internationalization.

HTML — Most Used Tags

In LWC templates, these are the HTML tags and patterns you will write most often.

  • <template> — root wrapper for every LWC markup file.
  • <div>, <span> — generic containers for layout and inline text.
  • <p>, <h1>-<h3> — headings and paragraphs for readable structure.
  • <ul>/<li> — lists for menus, options, or bullet points.
  • <template if:true={...}> / for:each — conditional display and loops inside LWC templates.
  • <lightning-input>, <lightning-combobox>, <lightning-button> — reusable Salesforce input components.
<template>
  <lightning-card title="Customer Details">
    <p>Name: {contactName}</p>
    <lightning-input label="Email" value={email} onchange={handleEmailChange}></lightning-input>
    <template if:true={hasPhone}>
      <p>Phone: {phoneNumber}</p>
    </template>
  </lightning-card>
</template>

HTML — Common Attributes

These attributes are the ones you use most in templates and markup.

  • class — attach scoped component styles.
  • data-* — store custom values for event handlers.
  • onclick / onchange — wire template events to component methods.
  • value / checked / disabled — bind input state to JavaScript properties.
  • for:key — use with repeaters (for:each) to keep DOM stable.
<template>
  <lightning-input
    class="field"
    type="text"
    value={name}
    onchange={handleNameChange}
    data-field="Name"
  ></lightning-input>

  <template for:each={items} for:item="item">
    <div key={item.id}>{item.label}</div>
  </template>
</template>

JavaScript — Most Used Basics

These JavaScript fundamentals are used most in LWC component classes and page logic.

  • let / const — const for values that don't change, let when state updates.
  • Data types — string, number, boolean, object, array, undefined / null.
  • Functions — event handlers, lifecycle helpers, and utility methods.
  • Arrow functions — short syntax and lexical this binding.
  • Async / await — handle Apex and promise-based code cleanly.
  • Import / export — bring in Apex methods, Lightning modules, and shared utilities.
import { LightningElement } from 'lwc';
import getContacts from '@salesforce/apex/ContactController.getContacts';

export default class ContactList extends LightningElement {
  contacts = [];
  isLoading = false;

  connectedCallback() {
    this.loadContacts();
  }

  async loadContacts() {
    this.isLoading = true;
    try {
      this.contacts = await getContacts();
    } finally {
      this.isLoading = false;
    }
  }

  get hasContacts() {
    return this.contacts.length > 0;
  }

  handleSearchChange(event) {
    const searchTerm = event.target.value;
    console.log('Search:', searchTerm);
  }
}

JavaScript — Essential Notes

These are the practical JS concepts that are especially helpful when learning LWC.

  • Template literals — use backticks for embedded values and multi-line strings.
  • Spread operator — copy arrays/objects without mutating the original.
  • Destructuring — pull out values from objects or arrays in one expression.
  • Array methods — map, filter, find, reduce are used for list data.
  • Event handling — templates wire events to JS methods with onclick, onchange, onsubmit.
  • Querying DOM — use this.template.querySelector() inside a component, never document.querySelector().
const values = [1, 2, 3];
const doubled = values.map(n => n * 2);

const user = { name: 'Maya', role: 'Admin' };
const { name, role } = user;

const clone = { ...user, role: 'User' };

const message = `Hello ${name}, you are ${role}`;

CSS — Most Used Selectors

These simple selectors cover the majority of styling needs in LWC components.

  • element — style tags directly, e.g. p, div.
  • .class — attach reusable styles to elements.
  • #id — target a unique element when needed.
  • [attribute] — style elements by attributes or data values.
  • p + p, div > span — common child/sibling selectors.
p {
  color: #c9d1d9;
  line-height: 1.6;
}

.card-title {
  font-size: 1.1rem;
  font-weight: 700;
}

[data-state="active"] {
  border-color: #58a6ff;
}

CSS — Common Patterns

These are the most useful CSS rules when building layouts and spacing in LWC.

  • Box model — margin, padding, border, width.
  • Flexbox — align rows and columns.
  • Responsive — use min-width and max-width for mobile.
  • Text — color, font-size, font-weight.
  • Spacing — use margin/padding consistently.
.row {
  display: flex;
  gap: 1rem;
  align-items: center;
}

.card {
  padding: 1rem;
  border-radius: 0.75rem;
}

@media (max-width: 600px) {
  .row {
    flex-direction: column;
  }
}
